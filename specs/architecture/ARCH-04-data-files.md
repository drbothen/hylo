# ARCH-04 — Data files: cache dir, atomic writes, reserved ledger

> Everything the status line persists and reads back, and the reserved published
> language it must not touch. Classification: `CacheStore` — **boundary**; the byte
> codec it uses is pure (ARCH-06).

## Layout

Cache dir resolution is `internal/platform.CacheDir()` (ARCH-05): macOS/Linux
`$XDG_CACHE_HOME/hylo` else `~/.cache/hylo` (relative/empty `XDG_*` ignored, OD-144);
Windows `%LOCALAPPDATA%\hylo\cache` (OD-144, separate `...\hylo\state` subdir for state).
Four legacy-compatible cache files, file-name formats are legacy-shared named constants
(T-061/T-062 class, "why not config": legacy must read the same names during cache-swap
tests):

| File (name format) | Contents | Writer contract |
|---|---|---|
| `statusline-<raw-sid>.json` | effective_rl / get_sample / proc_start session state | `json.dump` byte defaults (IM-03); raw sid per OD-03 |
| Mix cache (exact name format is the legacy-shared named constant owned by BC-1.03.002) | mix cache: `cur`, `mixv6` reset marker | same; sanitized per code point (BC-1.03.013) |
| `statusline-git-<sha1[:16]>.json` | branch/segment cache, 5 s TTL | same |
| `cost-history.json` | session cost history, status-line-owned (OD-124) | same; `record_cost` throttle strict `<` |

### Decision: Go is byte-exact cache writer and reader across Python/Go swaps (AD-08)

- **Context:** cache-swap coverage (BC-6.02.004) requires Python-writes/Go-reads and
  reverse for all four caches; Go `encoding/json` reorders keys and reformats floats.
- **Options considered:** (1) Go structs + `encoding/json`; (2) mutate-the-loaded-Value
  writers over `pyfmt.Value` ordered objects; (3) a bespoke cache file format.
- **Option 2.** Writers load with `pyfmt.Decode(text mode)`, mutate the ordered `Value`,
  and save with `pyfmt.Dumps`: separators `", "`/`": "`, `ensure_ascii`, no trailing
  newline, `NaN`/`Infinity` tokens, CPython float `repr`, int/float distinction preserved
  (`api_ms` stays int, BC-1.05.009), inherited insertion order (BC-1.04.020).
- **Rationale:** ruling (b) makes the Go writer byte-identical to `json.dump` defaults;
  mutating loaded values preserves key order with zero reformatting risk.
- **Consequences:** no cache struct exists anywhere; a cache-schema change is a
  `pyfmt.Value` surgery, not a struct edit; NaN usd bytes pinned by the oracle (OD-138).
- **Verification feasibility:** codec is **provable-grade** (63-case dump-length oracle,
  BC-5.02.002, generated by script — OD-142); cache writer bytes are **testable-only**
  at the seam but pinned by byte-for-byte swap tests (BC-6.02.004).

### Decision: atomic write with temp-file cleanup and Windows sharing-violation retry

- **Context:** legacy: `mkstemp` in the cache dir, mode 0600, `os.replace`; the temp
  leaks on a failed replace (BC-1.06.002); Windows rename under concurrent refresh can
  hit sharing violations (RK-3).
- **Options considered:** (1) replica leaks temps like legacy; (2) Go cleans up temps.
- **Option 2.** `os.CreateTemp(dir, base+".")`, chmod 0600, write, `os.Rename`; Go
  removes the temp on failure; on Windows sharing violations the INITIAL rename attempt
  plus `statusline.cache.rename_retry_limit` retries — total attempts = 1 + limit
  (three at the default; OD-188, pass-7 A19/OD-188 propagation: the retry COUNT shapes
  whether a Windows write persists, so it is config, D15) — sleeping
  `statusline.cache.rename_retry_delay_ms` between attempts (registry key, Int,
  default 10, range 1..1000, rationale code J — judgment call; D15: the timing value
  moves out of the code literal into the registry, OD-186).
- **Rationale:** stdout parity is unaffected; the Windows retry can PERSIST a cache
  write legacy (no retry, IM-17) would not — that byte divergence is covered by
  WIDENING the ruled `temp-file` exclusion's scope BY RULING (OD-186: temp names and
  cleanup AND the Windows sharing-violation rename-retry outcome), excluded only from
  the cache-file comparison (BC-6.03.003).
  Retry constants (Policy 16): `statusline.cache.rename_retry_limit` is a REGISTRY KEY
  (OD-188: Int, default 2, range 0..10, rationale code J — judgment call, beside
  `statusline.cache.rename_retry_delay_ms`; total attempts = 1 + limit, so three at
  the default — the count VP-018 pins at the default spelling). The default-2
  rationale (derived): the initial attempt plus two retries cover the
  transient sharing violation a
  live antivirus/indexer hold leaves on the just-written temp — more retries cannot
  shrink that window further on a sub-second refresh, RK-3);
  `statusline.cache.rename_retry_delay_ms` default 10 ms
  is a labeled judgment call (J, RK-3 carries no timing data): far below the 25 ms p95
  render budget, above scheduler noise, outlasting typical transient holds.
- **Verification feasibility:** fault-injection table tests (failed rename, closed dir,
  sid containing `/` — nothing persists, BC-1.06.002); **testable-only**, deliberately
  so, and covered by a named exclusion with its own table test.

## Temp-file cleanup (OD-110, OD-163)

Failed or interrupted saves remove **only their own temp** — the exact path
`os.CreateTemp` returned, removed on the failure path and nonexistent after a
successful rename (difference from legacy, named exclusion `temp-file` in the closed
set — scope widened by ruling OD-186 to cover the Windows sharing-violation
rename-retry outcome, pass-6 A09 — comparison carve-out per BC-6.03.003). **No sweeping** (OD-163): a Save never
scans for or deletes other temps, regardless of age or name. Several Claude Code
windows render concurrently and share `cost-history.json` and the caches, so one
process's Save must never delete another process's in-flight temp — the pass-2 defect
ADV-P2-A03/A2-15 (a swept ENOENT rename loses the other window's write). A temp left
behind by a killed process is therefore leaked exactly like legacy's, and rides the
same `temp-file` exclusion carve-out. Cleanup never runs at render time.

## Ledger: reserved published language (D7, OD-125)

The ledger file is the P3 writer's published language (D7: append-only JSONL, one
`write()` per line, schema frozen until P7). DI-007 is in force: **the status line never
reads it** — inputs are stdin, transcript, metrics store, own caches. ARCH-04 reserves
the boundary only: `paths.ledger` will live in the same registry (P3); the P1 skeleton
places no ledger code and defines no ledger types. REVISIT flag at P7 per OD-125.
