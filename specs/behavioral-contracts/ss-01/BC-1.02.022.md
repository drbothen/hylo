# Behavioral Contract BC-1.02.022: POSIX normpath keeps //

> Byte notation used below: `\e` = ESC (0x1B); `\0` = NUL (0x00). All other characters are literal UTF-8.

## Description

The project label is `basename(normpath(d)) or normpath(d)` (BC-1.02.003). Python's POSIX `normpath` keeps exactly
two leading slashes, so a project directory of `//` renders the label `//`, where Go's `filepath.Clean` would give
`/`. On Windows legacy uses `ntpath`, with its own results. The port uses per-OS ports of CPython `posixpath` and
`ntpath` (`pyfmt.PosixNormpath` / `pyfmt.NtNormpath` / `pyfmt.Basename`), never `filepath.Clean`.

## Preconditions

1. `d = workspace.project_dir or workspace.current_dir or cwd or ""` (BC-1.02.003) is a non-empty string.
2. The OS selects the path flavour: macOS and Linux → `posixpath`; Windows → `ntpath` (BC-5.03.004).
3. Default theme (OD-113): GREY `\e[90m`, RESET `\e[0m`.

## Postconditions

1. `pname = Basename(Normpath(d))`, or `Normpath(d)` when that basename is empty.
2. When `pname` is non-empty, the segment `\e[90m` + `pname` + `\e[0m` is appended after the model label (and after
   the git segment, when present).
3. POSIX results: `//` → `//`; `///` → `/`; `/` → `/`; `////x` → `x`; `//a//b/` → `b`; `/x/p/` → `p`; `.` → `.`;
   `/a/../b` → `b`; `a/` → `a`; `a\0b` → `a\0b` (NUL kept).
4. Windows (`ntpath`) results: `/` → `\`; `//` → `\\`; `///` → `\\\`; `//x` → `\\x`; `/a/../b` → `b`; `.` → `.`.

## Invariants

1. Go never uses `filepath.Clean`/`path.Clean` for this label (they give `/` for `//`).
2. OS-dependent results are committed as Python-written `*.windows.golden` files (design §5.1 Tier B); Go must
   match the golden of the OS it runs on. This is not an exclusion: the oracle itself is OS-dependent.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `d = "//"` on POSIX | label `//` |
| EC-002 | `d = "///"` on POSIX | label `/` |
| EC-003 | `d = "/"` on Windows | label `\` |
| EC-004 | `d = "//"` on Windows | label `\\` |
| EC-005 | `d = "//x"` on Windows | label `\\x` (UNC-like drive part kept) |
| EC-006 | `d` contains NUL | kept in the label |
| EC-007 | `d = ""` (all sources falsy) | no project segment (BC-1.02.003) |

## Canonical Test Vectors

stdin `{"workspace": {"project_dir": D}}` with git disabled; output is the project segment.

| Input D | Expected Output | Category |
|-------|----------------|----------|
| `"/x/p/"` (any OS) | `\e[90mp\e[0m` | happy-path |
| `"//"` (POSIX) | `\e[90m//\e[0m` | edge-case |
| `"///"` (POSIX) | `\e[90m/\e[0m` | edge-case |
| `"/a/../b"` (any OS) | `\e[90mb\e[0m` | edge-case |
| `"."` (any OS) | `\e[90m.\e[0m` | edge-case |
| `"//"` (Windows golden) | `\e[90m\\\e[0m` (label = two backslashes) | edge-case |
| `"/"` (Windows golden) | `\e[90m\\e[0m` (label = one backslash) | edge-case |

To avoid ambiguity: the Windows `//` label is the two bytes 0x5C 0x5C, the Windows `/` label is the single byte
0x5C. POSIX values pinned 2026-11-15 with the legacy `render_lane` under CPython 3.11; `ntpath` values pinned by
calling CPython 3.11 `ntpath.normpath`/`basename` (oracle, OD-104). The Windows goldens are regenerated by the
oracle on the Windows CI leg.
